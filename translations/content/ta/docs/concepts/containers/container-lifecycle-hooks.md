<!-- overview -->

இந்தப் பக்கம், kubelet நிர்வகிக்கும் கொள்கலன்கள் (Containers) எவ்வாறு
வாழ்க்கைச்சுழற்சி இணைப்பு (lifecycle hook) கட்டமைப்பை பயன்படுத்தி,
நிர்வாக நிகழ்வுகளின்போது குறியீட்டை இயக்கலாம் என்பதை விளக்குகிறது.

<!-- body -->

## மேலோட்டம்

Angular போன்ற பல நிரலாக்க மொழி கட்டமைப்புகள் கூறு வாழ்க்கைச்சுழற்சி
இணைப்புகளை வழங்குவதைப் போலவே, Kubernetes கொள்கலன்களுக்கு வாழ்க்கைச்சுழற்சி
இணைப்புகளை வழங்குகிறது. இந்த இணைப்புகள் கொள்கலன்களை தங்கள் நிர்வாக
வாழ்க்கைச்சுழற்சியில் நிகழும் நிகழ்வுகளை அறிந்து, தொடர்புடைய இணைப்பு
செயல்படுத்தப்படும்போது ஒரு கையாளுநரில் (handler) உள்ள குறியீட்டை இயக்க
அனுமதிக்கின்றன.

## கொள்கலன் இணைப்புகள்

கொள்கலன்களுக்கு வெளிப்படுத்தப்படும் இரண்டு இணைப்புகள் உள்ளன:

`PostStart`

இந்த இணைப்பு ஒரு கொள்கலன் உருவாக்கப்பட்ட உடனே செயல்படுத்தப்படுகிறது.
இது கொள்கலனின் `ENTRYPOINT` (முதன்மை செயல்முறை) உடன் **ஒரே நேரத்தில்**
இயங்குகிறது — அதாவது இணைப்பு முதன்மை செயல்முறைக்கு முன், போது அல்லது
பின்னர் இயங்கலாம். கையாளுநருக்கு எந்த அளவுருக்களும் (parameters) அனுப்பப்படுவதில்லை.

{{< note >}}
இணைப்பு கொள்கலன் செயல்முறையுடன் ஒரே நேரத்தில் இயங்கினாலும், அது
கொள்கலன் நிலை புதுப்பிப்புகளை தாமதப்படுத்தலாம்; இணைப்பு முடியும் வரை
கொள்கலன் `Running` நிலைக்கு மாறாமல் இருக்கலாம்.
{{< /note >}}

`PreStop`

இந்த இணைப்பு ஒரு கொள்கலன் API கோரிக்கை அல்லது உயிர்த்திருப்பு/தொடக்க
சோதனை தோல்வி, முன்னுரிமை பறிப்பு, வளப் போட்டி போன்ற நிர்வாக நிகழ்வு
காரணமாக நிறுத்தப்படுவதற்கு முன்னதாக அழைக்கப்படுகிறது. கொள்கலன் ஏற்கனவே
நிறுத்தப்பட்ட அல்லது முடிந்த நிலையில் இருந்தால் `PreStop` அழைப்பு தோல்வியடையும்;
கொள்கலனை நிறுத்த TERM சிக்னல் அனுப்பப்படுவதற்கு முன் இணைப்பு முடிந்திருக்க
வேண்டும். Pod இன் நிறுத்த கால இடைவெளி (termination grace period) `PreStop`
இணைப்பு செயல்படுத்தப்படுவதற்கு முன்னரே தொடங்குகிறது; எனவே கையாளுநரின்
முடிவு எதுவாக இருந்தாலும், கொள்கலன் இறுதியில் Pod இன் நிறுத்த கால
இடைவெளிக்குள் நிறுத்தப்படும். கையாளுநருக்கு எந்த அளவுருக்களும் அனுப்பப்படுவதில்லை.

நிறுத்த நடத்தையின் விரிவான விளக்கம்:
[Pod நிறுத்தம்](/docs/concepts/workloads/pods/pod-lifecycle/#pod-termination).

`StopSignal`

StopSignal வாழ்க்கைச்சுழற்சியை பயன்படுத்தி, கொள்கலன் நிறுத்தப்படும்போது
அனுப்பப்படும் நிறுத்த சிக்னலை வரையறுக்கலாம். இதை அமைத்தால், கொள்கலன்
பிம்பத்தில் (image) வரையறுக்கப்பட்ட `STOPSIGNAL` அறிவுறுத்தலை இது மேலெழுதும்.

தனிப்பயன் நிறுத்த சிக்னல்களுடன் நிறுத்த நடத்தையின் விரிவான விளக்கம்:
[நிறுத்த சிக்னல்கள்](/docs/concepts/workloads/pods/pod-lifecycle/#pod-termination-stop-signals).

### இணைப்பு கையாளுநர் செயலாக்கங்கள்

கொள்கலன்கள் ஒரு இணைப்புக்கான கையாளுநரை செயலாக்கி பதிவு செய்வதன் மூலம்
அந்த இணைப்பை அணுகலாம். கொள்கலன்களுக்காக மூன்று வகையான இணைப்பு
கையாளுநர்களை செயலாக்கலாம்:

* **Exec** — கொள்கலனின் cgroups மற்றும் namespaces க்குள் `pre-stop.sh` போன்ற
  குறிப்பிட்ட கட்டளையை இயக்குகிறது. கட்டளையால் பயன்படுத்தப்படும் வளங்கள்
  கொள்கலனுக்கு எதிராக கணக்கிடப்படும்.
* **HTTP** — கொள்கலனில் உள்ள குறிப்பிட்ட முனையத்திற்கு (endpoint) HTTP கோரிக்கையை
  செயல்படுத்துகிறது.
* **Sleep** — கொள்கலனை குறிப்பிட்ட காலத்திற்கு இடைநிறுத்துகிறது.

### இணைப்பு கையாளுநர் செயல்படுத்தல்

ஒரு கொள்கலன் வாழ்க்கைச்சுழற்சி நிர்வாக இணைப்பு அழைக்கப்படும்போது,
Kubernetes நிர்வாக அமைப்பு இணைப்பு செயலுக்கு (hook action) ஏற்ப கையாளுநரை
செயல்படுத்துகிறது. `httpGet`, `tcpSocket`
([நீக்கப்பட்டது](/docs/reference/generated/kubernetes-api/v1.35/#lifecyclehandler-v1-core))
மற்றும் `sleep` ஆகியவை kubelet செயல்முறையால் இயக்கப்படுகின்றன; `exec` கொள்கலனுக்குள்
இயக்கப்படுகிறது.

`PostStart` இணைப்பு கையாளுநர் அழைப்பு கொள்கலன் உருவாக்கப்படும்போது தொடங்குகிறது —
அதாவது கொள்கலனின் ENTRYPOINT மற்றும் `PostStart` இணைப்பு ஒரே நேரத்தில்
தூண்டப்படுகின்றன. (இதனால் `PostStart` க்கு HTTP hook பயன்படுத்துவது பொதுவாக
பொருத்தமற்றது, ஏனெனில் இணைப்பு இயங்கும்போது கொள்கலனின் செயல்முறை
முழுமையாக தொடங்கியிருக்கும் என்ற உத்தரவாதம் இல்லை.)
`PostStart` இணைப்பு செயல்படுத்தப்பட மிக அதிக நேரம் எடுத்தால் அல்லது
தொங்கினால் (hangs), கொள்கலன் `running` நிலைக்கு மாறுவதை தடுக்கலாம்.

`PreStop` இணைப்புகள் கொள்கலனை நிறுத்தும் சிக்னலிலிருந்து ஒத்திசைவற்ற முறையில்
(asynchronously) செயல்படுத்தப்படுவதில்லை; TERM சிக்னல் அனுப்பப்படுவதற்கு முன்
இணைப்பு தன் செயல்படுத்தலை முடிக்க வேண்டும். `PreStop` இணைப்பு செயல்படுத்தலின்
போது தொங்கினால், Pod இன் நிலை `Terminating` ஆக இருக்கும் மற்றும் அதன்
`terminationGracePeriodSeconds` முடியும் வரை அப்படியே இருக்கும். இந்த கால
இடைவெளி `PreStop` இணைப்பு செயல்படுத்தப்படும் நேரம் மற்றும் கொள்கலன் இயல்பாக
நிறுத்தப்படும் நேரம் இரண்டையும் உள்ளடக்கியது. எடுத்துக்காட்டாக,
`terminationGracePeriodSeconds` 60 என்றும், இணைப்பு 55 விநாடிகள் எடுத்துக்கொண்டால்,
கொள்கலன் சிக்னல் பெற்ற பிறகு இயல்பாக நிறுத்தப்பட 10 விநாடிகள் எடுத்தால்,
மொத்த நேரம் (55+10=65) `terminationGracePeriodSeconds` ஐ விட அதிகமாக இருப்பதால்
கொள்கலன் இயல்பாக நிறுத்தப்படுவதற்கு முன்னரே கொல்லப்படும்.

`PostStart` அல்லது `PreStop` இணைப்பு தோல்வியடைந்தால், அது கொள்கலனை கொல்லும்.

பயனர்கள் தங்கள் இணைப்பு கையாளுநர்களை முடிந்தவரை இலகுவாக (lightweight)
வைத்திருக்க வேண்டும். இருப்பினும், கொள்கலனை நிறுத்துவதற்கு முன் நிலையை
சேமிப்பது போன்ற சந்தர்ப்பங்களில் நீண்ட நேரம் இயங்கும் கட்டளைகள் அர்த்தமுள்ளதாக இருக்கும்.

### இணைப்பு வழங்கல் உத்தரவாதங்கள்

இணைப்பு வழங்கல் *குறைந்தது ஒரு முறை* (at least once) என்று நோக்கப்படுகிறது —
அதாவது `PostStart` அல்லது `PreStop` போன்ற எந்த நிகழ்வுக்கும் ஒரு இணைப்பு
பலமுறை அழைக்கப்படலாம். இதை சரியாக கையாள்வது இணைப்பு செயலாக்கத்தின்
பொறுப்பாகும்.

பொதுவாக, ஒற்றை வழங்கல் மட்டுமே செய்யப்படுகிறது. எடுத்துக்காட்டாக, ஒரு
HTTP இணைப்பு பெறுநர் செயலற்று இருந்தால், மீண்டும் அனுப்ப முயற்சி செய்யப்படுவதில்லை.
ஆயினும், அரிதான சில சந்தர்ப்பங்களில் இரட்டை வழங்கல் நிகழலாம். எடுத்துக்காட்டாக,
ஒரு kubelet ஒரு இணைப்பை அனுப்பும் நடுவில் மறுதொடக்கம் (restart) ஆனால்,
kubelet மீண்டும் இயங்கத் தொடங்கிய பிறகு இணைப்பு மீண்டும் அனுப்பப்படலாம்.

### இணைப்பு கையாளுநர்களை பிழையறிதல்

இணைப்பு கையாளுநரின் பதிவுகள் (logs) Pod நிகழ்வுகளில் (events) காட்டப்படுவதில்லை.
ஒரு கையாளுநர் ஏதேனும் காரணத்தால் தோல்வியடைந்தால், அது ஒரு நிகழ்வை
ஒளிபரப்புகிறது. `PostStart` க்கு இது `FailedPostStartHook` நிகழ்வாகவும்,
`PreStop` க்கு இது `FailedPreStopHook` நிகழ்வாகவும் இருக்கும்.
`FailedPostStartHook` நிகழ்வை நீங்களே உருவாக்க,
[lifecycle-events.yaml](https://k8s.io/examples/pods/lifecycle-events.yaml)
கோப்பில் postStart கட்டளையை "badcommand" என மாற்றி பயன்படுத்துங்கள்.
`kubectl describe pod lifecycle-demo` இயக்கும்போது காணும் நிகழ்வுகளின்
எடுத்துக்காட்டு வெளியீடு:

```
Events:
  Type     Reason               Age              From               Message
  ----     ------               ----             ----               -------
  Normal   Scheduled            7s               default-scheduler  Successfully assigned default/lifecycle-demo to ip-XXX-XXX-XX-XX.us-east-2...
  Normal   Pulled               6s               kubelet            Successfully pulled image "nginx" in 229.604315ms
  Normal   Pulling              4s (x2 over 6s)  kubelet            Pulling image "nginx"
  Normal   Created              4s (x2 over 5s)  kubelet            Created container lifecycle-demo-container
  Normal   Started              4s (x2 over 5s)  kubelet            Started container lifecycle-demo-container
  Warning  FailedPostStartHook  4s (x2 over 5s)  kubelet            Exec lifecycle hook ([badcommand]) for Container "lifecycle-demo-container" in Pod "lifecycle-demo_default(30229739-9651-4e5a-9a32-a8f1688862db)" failed - error: command 'badcommand' exited with 126: , message: "OCI runtime exec failed: exec failed: container_linux.go:380: starting container process caused: exec: \"badcommand\": executable file not found in $PATH: unknown\r\n"
  Normal   Killing              4s (x2 over 5s)  kubelet            FailedPostStartHook
  Normal   Pulled               4s               kubelet            Successfully pulled image "nginx" in 215.66395ms
  Warning  BackOff              2s (x2 over 3s)  kubelet            Back-off restarting failed container
```
