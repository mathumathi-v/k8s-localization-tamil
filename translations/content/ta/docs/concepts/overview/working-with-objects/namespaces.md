<!-- overview -->
Kubernetes-இல், _namespaces_ (பெயரிடல் வெளிகள்) என்பவை ஒரே ஒரு கொத்தில் (Cluster) உள்ள வளங்களின் குழுக்களை தனிமைப்படுத்துவதற்கான ஒரு வழிமுறையை வழங்குகின்றன. வளங்களின் பெயர்கள் ஒரு பெயரிடல் வெளிக்குள் தனித்துவமாக இருக்க வேண்டும், ஆனால் வேறு பெயரிடல் வெளிகளில் இருக்க வேண்டியதில்லை.

<!-- body -->
## பல பெயரிடல் வெளிகளை எப்போது பயன்படுத்த வேண்டும்

Namespaces (பெயரிடல் வெளிகள்) என்பவை பல குழுக்களில் பரவியுள்ள பலர் பயன்படுத்தும் சூழல்களுக்காக வடிவமைக்கப்பட்டவை. சில நபர்கள் முதல் பத்துக்கும் குறைவான பயனர்களைக் கொண்ட கொத்துகளுக்கு (Clusters), நீங்கள் பெயரிடல் வெளிகளை உருவாக்குவது அல்லது அவற்றைப் பற்றி சிந்திப்பது தேவையில்லை. பெயரிடல் வெளிகள் பெயர்களுக்கு ஒரு வரம்பை வழங்குகின்றன. வளங்களின் பெயர்கள் ஒரு பெயரிடல் வெளிக்குள் தனித்துவமாக இருக்க வேண்டும், ஆனால் வேறு பெயரிடல் வெளிகளில் இருக்க வேண்டியதில்லை. பெயரிடல் வெளிகளை உள்ளமைக்க (nested) முடியாது. பெயரிடல் வெளிகள் என்பவை கொத்து வளங்களை (Cluster resources) பல பயனர்களிடையே பகிர்வதற்கான ஒரு வழியாகும் (வள ஒதுக்கீட்டின் (resource quota) மூலம்).

{{< note >}}
உற்பத்தி கொத்திற்கு (production cluster), `default` பெயரிடல் வெளியை _பயன்படுத்தாமல்_ இருப்பதை பரிசீலியுங்கள். அதற்கு பதிலாக, மற்ற பெயரிடல் வெளிகளை உருவாக்கி அவற்றைப் பயன்படுத்துங்கள்.
{{< /note >}}

## ஆரம்ப பெயரிடல் வெளிகள்

Kubernetes நான்கு ஆரம்ப பெயரிடல் வெளிகளுடன் தொடங்குகிறது:

`default`: முதலில் பெயரிடல் வெளி உருவாக்காமலேயே உங்கள் புதிய கொத்தை பயன்படுத்த ஆரம்பிக்கலாம் என்பதற்காக Kubernetes இந்த பெயரிடல் வெளியை உள்ளடக்குகிறது.

`kube-node-lease`: ஒவ்வொரு Node-உடனும் தொடர்புடைய Lease பொருள்களை (objects) வைத்திருக்கிறது.

`kube-public`: அனைத்து கிளையண்டுகளாலும் (clients) படிக்கக்கூடியது. பெரும்பாலும் கொத்து பயன்பாட்டிற்காக ஒதுக்கப்பட்டுள்ளது.

`kube-system`: Kubernetes அமைப்பால் (system) உருவாக்கப்பட்ட பொருள்களுக்கான பெயரிடல் வெளி.

## பெயரிடல் வெளிகளுடன் பணிபுரிதல்

{{< note >}}
`kube-` என்ற முன்னொட்டுடன் (prefix) பெயரிடல் வெளிகளை உருவாக்குவதை தவிர்க்கவும், ஏனெனில் அது Kubernetes அமைப்பு பெயரிடல் வெளிகளுக்காக ஒதுக்கப்பட்டுள்ளது.
{{< /note >}}

### பெயரிடல் வெளிகளை காண்பது

```shell
kubectl get namespace
```

### ஒரு கோரிக்கைக்கான பெயரிடல் வெளியை அமைத்தல்

```shell
kubectl run nginx --image=nginx --namespace=<insert-namespace-name-here>
kubectl get pods --namespace=<insert-namespace-name-here>
```

### பெயரிடல் வெளி விருப்பத்தை அமைத்தல்

```shell
kubectl config set-context --current --namespace=<insert-namespace-name-here>
kubectl config view --minify | grep namespace:
```

## பெயரிடல் வெளிகளும் DNS-உம்

நீங்கள் ஒரு Service (சேவை) உருவாக்கும்போது, அது `<service-name>.<namespace-name>.svc.cluster.local` என்ற வடிவத்தில் ஒரு தொடர்புடைய DNS பதிவை (entry) உருவாக்குகிறது. ஒரு கொள்கலன் (Container) `<service-name>` மட்டும் பயன்படுத்தினால், அது ஒரு பெயரிடல் வெளிக்கு உள்ளூராக (local) உள்ள சேவையாக (Service) தீர்க்கப்படும். பெயரிடல் வெளிகளைக் கடந்து செல்ல, FQDN (முழுத் தகுதி வாய்ந்த டொமைன் பெயர்) பயன்படுத்தவும்.

## அனைத்து பொருள்களும் பெயரிடல் வெளியில் இல்லை

பெரும்பாலான Kubernetes வளங்கள் (resources) ஏதோ ஒரு பெயரிடல் வெளியில் உள்ளன. இருப்பினும் பெயரிடல் வெளி வளங்கள் (namespace resources) தாமே ஒரு பெயரிடல் வெளியில் இல்லை. Node-கள் மற்றும் persistentVolumes போன்ற குறைந்த-நிலை (low-level) வளங்கள் எந்த பெயரிடல் வெளியிலும் இல்லை.

```shell
kubectl api-resources --namespaced=true
kubectl api-resources --namespaced=false
```

## தானியங்கி முத்திரையிடல் (Automatic labelling)

Kubernetes கட்டுப்பாட்டு தளம் (control plane) அனைத்து பெயரிடல் வெளிகளிலும் மாற்றமுடியாத முத்திரையை (Label) `kubernetes.io/metadata.name` என்று அமைக்கிறது.

## அடுத்தது என்ன

பெயரிடல் வெளிகளை உருவாக்குவது மற்றும் நீக்குவது பற்றி மேலும் அறியுங்கள்.
