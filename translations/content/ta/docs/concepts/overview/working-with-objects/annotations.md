<!-- body -->
## பொருள்களுடன் மெட்டாடேட்டா இணைத்தல்

Kubernetes பொருள்களுடன் மெட்டாடேட்டா இணைக்க முத்திரைகள் (Labels) அல்லது
குறிப்புகள் (Annotations) இரண்டையும் பயன்படுத்தலாம். முத்திரைகள் (Labels)
பொருள்களை தேர்ந்தெடுக்கவும், குறிப்பிட்ட நிபந்தனைகளை நிறைவேற்றும்
பொருள்களின் தொகுப்புகளை கண்டறியவும் பயன்படுத்தப்படலாம். இதற்கு மாறாக,
குறிப்புகள் (Annotations) பொருள்களை அடையாளம் காணவும் தேர்ந்தெடுக்கவும்
பயன்படுத்தப்படுவதில்லை. ஒரு குறிப்பில் (Annotation) உள்ள மெட்டாடேட்டா
சிறியதாகவோ அல்லது பெரியதாகவோ, கட்டமைக்கப்பட்டதாகவோ அல்லது
கட்டமைக்கப்படாததாகவோ இருக்கலாம், மேலும் முத்திரைகளால் (Labels) அனுமதிக்கப்படாத
எழுத்துக்களையும் கொண்டிருக்கலாம். ஒரே பொருளின் மெட்டாடேட்டாவில் முத்திரைகள்
(Labels) மற்றும் குறிப்புகள் (Annotations) இரண்டையும் பயன்படுத்துவது சாத்தியமாகும்.

முத்திரைகளைப் (Labels) போலவே, குறிப்புகளும் (Annotations) key/value வரைபடங்கள் ஆகும்:

```json
"metadata": {
  "annotations": {
    "key1" : "value1",
    "key2" : "value2"
  }
}
```

{{< note >}}
வரைபடத்தில் உள்ள விசைகளும் (keys) மதிப்புகளும் (values) சரங்களாக (strings)
இருக்க வேண்டும். வேறு வார்த்தைகளில் கூறுவதானால், விசைகளுக்கோ அல்லது
மதிப்புகளுக்கோ எண், boolean, பட்டியல் அல்லது பிற வகைகளை பயன்படுத்த முடியாது.
{{< /note >}}

குறிப்புகளில் (Annotations) பதிவு செய்யக்கூடிய சில தகவல்களின் எடுத்துக்காட்டுகள்
பின்வருமாறு:

* ஒரு அறிவிப்பு-அடிப்படையிலான (declarative) கட்டமைப்பு அடுக்கால் நிர்வகிக்கப்படும்
  புலங்கள். இந்தப் புலங்களை குறிப்புகளாக (Annotations) இணைப்பது, அவற்றை
  கிளையண்டுகள் அல்லது சேவையகங்களால் அமைக்கப்பட்ட இயல்புநிலை மதிப்புகளிலிருந்தும்,
  தானாக உருவாக்கப்பட்ட புலங்களிலிருந்தும், தானாக அளவிடல் (auto-sizing) அல்லது
  தானாக அளவீடு (auto-scaling) அமைப்புகளால் அமைக்கப்பட்ட புலங்களிலிருந்தும்
  வேறுபடுத்துகிறது.

* நேர முத்திரைகள் (timestamps), வெளியீட்டு IDகள், git கிளை, PR எண்கள்,
  படத்தொகுப்பு (image) hash மதிப்புகள் மற்றும் பதிவேட்டு முகவரி போன்ற
  உருவாக்கம் (Build), வெளியீடு (release) அல்லது படத்தொகுப்பு (image) தகவல்கள்.

* பதிவு (logging), கண்காணிப்பு (monitoring), பகுப்பாய்வு (analytics) அல்லது
  தணிக்கை (audit) களஞ்சியங்களுக்கான சுட்டிகள்.

* பிழைகண்டறிதல் நோக்கங்களுக்கு பயன்படுத்தக்கூடிய கிளையண்ட் நூலகம் அல்லது
  கருவி தகவல்கள்: எடுத்துக்காட்டாக, பெயர், பதிப்பு மற்றும் உருவாக்க தகவல்.

* பிற சுற்றுச்சூழல் அமைப்பு கூறுகளிலிருந்து தொடர்புடைய பொருள்களின் URL போன்ற
  பயனர் அல்லது கருவி/அமைப்பு தோற்றம் தொடர்பான தகவல்கள்.

* இலகுவான வெளியீட்டு கருவி மெட்டாடேட்டா: எடுத்துக்காட்டாக, config அல்லது
  checkpoints.

* பொறுப்பான நபர்களின் தொலைபேசி அல்லது பேஜர் எண்கள், அல்லது அந்தத் தகவல்கள்
  எங்கே காணலாம் என்று குறிப்பிடும் கோப்பக உள்ளீடுகள், எடுத்துக்காட்டாக
  ஒரு குழுவின் இணைய தளம்.

* இறுதிப் பயனரிடமிருந்து செயலாக்கங்களுக்கு நடத்தையை மாற்றவோ அல்லது
  நிலையற்ற அம்சங்களை இயக்கவோ உதவும் வழிகாட்டுதல்கள்.

குறிப்புகளை (Annotations) பயன்படுத்துவதற்கு பதிலாக, இந்த வகையான தகவல்களை
வெளிப்புற தரவுத்தளத்திலோ அல்லது கோப்பகத்திலோ சேமிக்கலாம், ஆனால் அது
பகிர்வு கிளையண்ட் நூலகங்கள் மற்றும் வரிசைப்படுத்தல் (deployment), நிர்வாகம்
(management), ஆய்வு (introspection) போன்றவற்றுக்கான கருவிகளை உருவாக்குவதை
மிகவும் கடினமாக்கும்.

## தொடரியல் மற்றும் எழுத்துத் தொகுப்பு (Syntax and character set)

_குறிப்புகள் (Annotations)_ என்பவை key/value இணைகள். சரியான குறிப்பு விசைகளுக்கு
(annotation keys) இரண்டு பகுதிகள் உள்ளன: ஒரு விருப்பமான முன்னொட்டு (prefix)
மற்றும் பெயர் (name), ஒரு சாய்கோடு (`/`) மூலம் பிரிக்கப்படுகின்றன. பெயர் பகுதி
கட்டாயமானது மற்றும் 63 எழுத்துக்கள் அல்லது அதற்கும் குறைவாக இருக்க வேண்டும்,
ஒரு எண்-எழுத்து எழுத்தில் (`[a-z0-9A-Z]`) தொடங்கி மற்றும் முடிவடைய வேண்டும்,
மற்றும் இடையில் கோடுகள் (`-`), அடிக்கோடுகள் (`_`), புள்ளிகள் (`.`) மற்றும்
எண்-எழுத்துக்களை கொண்டிருக்கலாம். முன்னொட்டு (prefix) விருப்பமானது. குறிப்பிடப்பட்டால்,
முன்னொட்டு ஒரு DNS துணை-டொமைனாக (subdomain) இருக்க வேண்டும்: புள்ளிகளால் (`.`)
பிரிக்கப்பட்ட DNS பெயர் முத்திரைகளின் (labels) தொடர், மொத்தத்தில் 253 எழுத்துக்களுக்கு
மிகாமல், ஒரு சாய்கோட்டால் (`/`) தொடர்ந்து வருகிறது.

முன்னொட்டு தவிர்க்கப்பட்டால், குறிப்பு விசை (annotation key) பயனருக்கு தனிப்பட்டதாக
கருதப்படும். இறுதிப் பயனர் பொருள்களுக்கு குறிப்புகள் சேர்க்கும் தானியங்கி அமைப்பு
கூறுகள் (எ.கா. `kube-scheduler`, `kube-controller-manager`, `kube-apiserver`,
`kubectl`, அல்லது பிற மூன்றாம் தரப்பு தானியங்கி அமைப்புகள்) ஒரு முன்னொட்டை
குறிப்பிட வேண்டும்.

`kubernetes.io/` மற்றும் `k8s.io/` முன்னொட்டுகள் Kubernetes முக்கிய கூறுகளுக்காக
ஒதுக்கப்பட்டுள்ளன.

எடுத்துக்காட்டாக, `imageregistry: https://hub.docker.com/` என்ற குறிப்பை
கொண்ட ஒரு Pod-க்கான (பாட்) இயக்கக் கோப்பு (manifest) இங்கே உள்ளது:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: annotations-demo
  annotations:
    imageregistry: "https://hub.docker.com/"
spec:
  containers:
  - name: nginx
    image: nginx:1.14.2
    ports:
    - containerPort: 80
```
