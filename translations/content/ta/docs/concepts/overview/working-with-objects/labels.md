_முத்திரைகள் (Labels)_ என்பவை Pods போன்ற பொருட்களுடன் இணைக்கப்படும் key/value இணைகளாகும். முத்திரைகள், பயனர்களுக்கு அர்த்தமுள்ளதாகவும் தொடர்புடையதாகவும் இருக்கும் பொருட்களின் அடையாளப் பண்புகளை குறிப்பிடப் பயன்படுகின்றன; ஆனால் அவை முக்கிய அமைப்பிற்கு நேரடியாக எந்த அர்த்தத்தையும் உணர்த்துவதில்லை. முத்திரைகள், பொருட்களை ஒழுங்கமைக்கவும், பொருட்களின் துணைக்குழுக்களைத் தேர்ந்தெடுக்கவும் பயன்படுத்தப்படலாம். முத்திரைகளை உருவாக்கும் நேரத்தில் பொருட்களுடன் இணைக்கலாம், மேலும் எந்த நேரத்திலும் சேர்க்கலாம் மற்றும் மாற்றலாம். ஒவ்வொரு பொருளும் key/value முத்திரைகளின் தொகுப்பை வரையறுக்கலாம். கொடுக்கப்பட்ட ஒரு பொருளுக்கு ஒவ்வொரு Key-உம் தனித்துவமாக இருக்க வேண்டும்.

முத்திரைகள், திறமையான வினவல்கள் (queries) மற்றும் கண்காணிப்புகளை (watches) அனுமதிக்கின்றன, மேலும் UI-கள் மற்றும் CLI-களில் பயன்படுத்த ஏற்றதாக உள்ளன. அடையாளப்படுத்தாத தகவல்கள் குறிப்புகளை (Annotations) பயன்படுத்தி பதிவு செய்யப்பட வேண்டும்.

## நோக்கம் (Motivation)

முத்திரைகள், பயனர்கள் தங்கள் சொந்த நிறுவன கட்டமைப்புகளை தளர்வான முறையில் கணினி பொருட்களுடன் இணைத்துக்கொள்ள உதவுகின்றன.

முத்திரை எடுத்துக்காட்டுகள்:
* `"release" : "stable"`, `"release" : "canary"`
* `"environment" : "dev"`, `"environment" : "qa"`, `"environment" : "production"`
* `"tier" : "frontend"`, `"tier" : "backend"`, `"tier" : "cache"`
* `"partition" : "customerA"`, `"partition" : "customerB"`

## தொடரியல் மற்றும் எழுத்துக்கள் (Syntax and character set)

முத்திரைகள் key/value இணைகளாகும். செல்லுபடியாகும் முத்திரை key-களில் இரண்டு பகுதிகள் உள்ளன: ஒரு விரும்பினால் சேர்க்கக்கூடிய முன்னொட்டு (prefix) மற்றும் பெயர் (name), இவை ஒரு சாய்வு கோடு (/) மூலம் பிரிக்கப்படும். பெயர் பகுதி கட்டாயமாக இருக்க வேண்டும் மற்றும் 63 எழுத்துகள் அல்லது அதற்கும் குறைவாக இருக்க வேண்டும். முன்னொட்டு விரும்பினால் சேர்க்கலாம். குறிப்பிட்டால், அது ஒரு DNS துணைக்களம் (subdomain) ஆக இருக்க வேண்டும்.

`kubernetes.io/` மற்றும் `k8s.io/` முன்னொட்டுகள் Kubernetes முக்கிய கூறுகளுக்காக ஒதுக்கப்பட்டுள்ளன.

செல்லுபடியாகும் முத்திரை மதிப்பு: 63 எழுத்துகள் அல்லது அதற்கும் குறைவாக இருக்க வேண்டும், எண்-எழுத்து (alphanumeric) எழுத்தில் தொடங்கி முடிய வேண்டும்.

## முத்திரை தேர்வாளர்கள் (Label selectors)

ஒரு _முத்திரை தேர்வாளர் (label selector)_ மூலம், கிளையன்ட்/பயனர் பொருட்களின் தொகுப்பை அடையாளம் காண முடியும். முத்திரை தேர்வாளர் என்பது Kubernetes-இல் உள்ள முக்கிய குழுவாக்கும் அடிப்படை (core grouping primitive) ஆகும்.

API இரண்டு வகைகளை ஆதரிக்கிறது: _சமத்துவ அடிப்படையிலான (equality-based)_ மற்றும் _தொகுப்பு அடிப்படையிலான (set-based)_. பல தேவைகள் (requirements) கமா மூலம் பிரிக்கப்படுகின்றன (AND செயற்குறி).

### சமத்துவ அடிப்படையிலான தேவை (Equality-based requirement)

மூன்று செயற்குறிகள்: `=`, `==`, `!=`

எடுத்துக்காட்டு: `environment = production`, `tier != frontend`

### தொகுப்பு அடிப்படையிலான தேவை (Set-based requirement)

மூன்று செயற்குறிகள்: `in`, `notin`, `exists`

எடுத்துக்காட்டு: `environment in (production, qa)`, `tier notin (frontend, backend)`

## API

### LIST மற்றும் WATCH வடிகட்டல் (LIST and WATCH filtering)

சமத்துவ அடிப்படையிலான மற்றும் தொகுப்பு அடிப்படையிலான தேர்வாளர்கள் இரண்டையும் பயன்படுத்தலாம்:

```shell
kubectl get pods -l environment=production,tier=frontend
kubectl get pods -l 'environment in (production),tier in (frontend)'
```

### API பொருட்களில் தொகுப்பு குறிப்புகள் (Set references in API objects)

Service மற்றும் ReplicationController சமத்துவ அடிப்படையிலான தேர்வாளர்களைப் பயன்படுத்துகின்றன.

புதிய வளங்கள் (Job, Deployment, ReplicaSet, DaemonSet) `matchLabels` மற்றும் `matchExpressions` மூலம் தொகுப்பு அடிப்படையிலான தேவைகளை ஆதரிக்கின்றன.

## முத்திரைகளை திறம்படப் பயன்படுத்துதல் (Using labels effectively)

வெவ்வேறு பயன்பாடுகள் `app` முத்திரைக்கு வெவ்வேறு மதிப்புகளைப் பயன்படுத்துகின்றன. பல அடுக்கு (multi-tier) பயன்பாடுகள் ஒவ்வொரு அடுக்கையும் தனித்துவமாக அடையாளம் காண வேண்டும்.

## முத்திரைகளை புதுப்பித்தல் (Updating labels)

```shell
kubectl label pods -l app=nginx tier=fe
```

## அடுத்த கட்டங்கள் (What's next)

ஒரு Node-க்கு முத்திரை சேர்ப்பது எப்படி என்பதை அறியவும், நன்கு அறியப்பட்ட முத்திரைகளைக் கண்டறியவும், பரிந்துரைக்கப்பட்ட முத்திரைகளைப் பார்க்கவும்.
