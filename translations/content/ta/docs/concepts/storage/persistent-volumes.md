இந்த ஆவணம் Kubernetes இல் உள்ள _நிலையான தொகுதிகளை (PersistentVolumes)_ விவரிக்கிறது. [தொகுதிகள் (Volumes)](/docs/concepts/storage/volumes/) பற்றிய அறிவு பரிந்துரைக்கப்படுகிறது.

<!-- body -->

## அறிமுகம் (Introduction)

சேமிப்பகத்தை நிர்வகிப்பது, கணக்கீட்டு நிகழ்வுகளை (compute instances) நிர்வகிப்பதிலிருந்து வேறுபட்ட ஒரு பிரச்சனையாகும். PersistentVolume துணை அமைப்பு (subsystem), சேமிப்பகம் எவ்வாறு வழங்கப்படுகிறது என்பதன் விவரங்களை, அது எவ்வாறு பயன்படுத்தப்படுகிறது என்பதிலிருந்து தனிமைப்படுத்தும் ஒரு API ஐ பயனர்களுக்கும் நிர்வாகிகளுக்கும் (administrators) வழங்குகிறது. இதற்காக இரண்டு API வளங்கள் (resources) அறிமுகப்படுத்தப்படுகின்றன: PersistentVolume மற்றும் PersistentVolumeClaim.

**PersistentVolume (PV)** என்பது ஒரு நிர்வாகியால் வழங்கப்பட்ட அல்லது StorageClass ஐப் பயன்படுத்தி மாறும் வகையில் (dynamically) வழங்கப்பட்ட கொத்தில் (Cluster) உள்ள சேமிப்பகத்தின் ஒரு பகுதியாகும். இது Node போன்ற ஒரு கொத்து வளமாகும் (cluster resource). PV கள் Volumes போன்ற தொகுதி சொருகிகளை (volume plugins) கொண்டுள்ளன, ஆனால் அந்த PV ஐப் பயன்படுத்தும் தனிப்பட்ட Pod இலிருந்து சுயாதீனமான (independent) வாழ்க்கைச் சுழற்சியை (lifecycle) கொண்டுள்ளன.

**PersistentVolumeClaim (PVC)** என்பது ஒரு பயனரின் சேமிப்பக கோரிக்கையாகும். இது ஒரு Pod ஐப் போன்றது. Pod கள் Node வளங்களை (resources) உட்கொள்கின்றன; PVC கள் PV வளங்களை உட்கொள்கின்றன. Pod கள் குறிப்பிட்ட அளவிலான வளங்களை (CPU மற்றும் நினைவகம்) கோரலாம். கோரிக்கைகள் (Claims) குறிப்பிட்ட அளவு மற்றும் அணுகல் முறைகளை (access modes) கோரலாம்.

PersistentVolumeClaim கள் பயனர்கள் தனிமைப்படுத்தப்பட்ட (abstracted) PersistentVolume கள் எவ்வாறு செயல்படுத்தப்படுகின்றன என்பது பற்றி கவலைப்படாமல் சேமிப்பக வளங்களை பயன்படுத்த அனுமதிக்கின்றன. நிர்வாகிகள் வெவ்வேறு அளவு மற்றும் அணுகல் முறைகளுடன் PV களை வழங்க வேண்டும், பயனர்கள் PVC கள் மூலம் தங்களுக்கு தேவையான சேமிப்பகத்தை கோர வேண்டும்.

## தொகுதிகள் மற்றும் கோரிக்கைகளின் வாழ்க்கைச் சுழற்சி (Lifecycle of a Volume and Claim)

PV கள் கொத்தில் உள்ள வளங்கள். PVC கள் அந்த வளங்களுக்கான கோரிக்கைகள் மற்றும் வள கோரிக்கைகளுக்கான சரிபார்ப்புகளாக (checks) செயல்படுகின்றன. PV கள் மற்றும் PVC கள் இடையேயான இடைவினை பின்வரும் வாழ்க்கைச் சுழற்சியை பின்பற்றுகிறது:

### வழங்கல் (Provisioning)

PV கள் இரண்டு வழிகளில் வழங்கப்படலாம்: நிலையாக (statically) அல்லது மாறும் வகையில் (dynamically).

#### நிலையான வழங்கல் (Static Provisioning)

ஒரு கொத்து நிர்வாகி பல PV களை உருவாக்குகிறார். அவை கொத்து பயனர்களுக்கு பயன்படுத்தக் கூடிய உண்மையான சேமிப்பகத்தின் விவரங்களை கொண்டிருக்கும். அவை Kubernetes API இல் இருக்கும் மற்றும் பயன்படுத்தலுக்கு கிடைக்கும்.

#### மாறும் வழங்கல் (Dynamic Provisioning)

நிர்வாகி உருவாக்கிய நிலையான PV களில் எதுவும் ஒரு PersistentVolumeClaim உடன் பொருந்தவில்லை என்றால், கொத்து PVC க்காக சிறப்பாக ஒரு தொகுதியை (volume) மாறும் வகையில் வழங்க முயற்சிக்கலாம். இந்த வழங்கல் StorageClass களை அடிப்படையாகக் கொண்டது: PVC ஒரு [StorageClass](/docs/concepts/storage/storage-classes/) ஐ கோர வேண்டும், மேலும் நிர்வாகி அந்த மாறும் வழங்கல் நிகழ வேண்டும் என்பதற்காக அந்த வகுப்பை உருவாக்கி உள்ளமைத்திருக்க (configure) வேண்டும். `""` வகுப்பை கோரும் கோரிக்கைகள் மாறும் வழங்கலை திறம்பட முடக்குகின்றன.

மாறும் சேமிப்கத்தை இயக்க, நிர்வாகி API சேவையகத்தில் (API server) `DefaultStorageClass` [நுழைவு கட்டுப்பாட்டாளரை (admission controller)](/docs/reference/access-authn-authz/admission-controllers/#defaultstorageclass) இயக்க வேண்டும்.

### பிணைப்பு (Binding)

ஒரு பயனர் ஒரு PersistentVolumeClaim ஐ குறிப்பிட்ட அளவு சேமிப்பக கோரிக்கை மற்றும் சில அணுகல் முறைகளுடன் உருவாக்குகிறார். கட்டுப்பாட்டு விமானத்தில் (control plane) ஒரு கட்டுப்படுத்தி (controller) புதிய PVC களை கண்காணித்து, பொருந்தக்கூடிய PV ஐ கண்டுபிடித்து, அவற்றை ஒன்றாக இணைக்கும் (binds them together). PV மாறும் வகையில் வழங்கப்பட்டிருந்தால், கட்டுப்படுத்தி எப்போதும் அந்த PV ஐ PVC உடன் இணைக்கும். இல்லையெனில், பயனர் எப்போதும் குறைந்தபட்சம் அவர்கள் கோரியதை பெறுவார், ஆனால் தொகுதி கோரிக்கையை விட அதிகமாக இருக்கலாம்.

கோரிக்கைகள் பொருந்தும் தொகுதி இல்லாத நிலையில் பிணைக்கப்படாமல் எல்லையற்ற காலத்திற்கு இருக்கும். பொருந்தக்கூடிய தொகுதிகள் கிடைக்கும்போது கோரிக்கைகள் இணைக்கப்படும். உதாரணமாக, பல 50Gi PV களுடன் வழங்கப்பட்ட கொத்து 100Gi கோரும் PVC உடன் பொருந்தாது. 100Gi PV கொத்தில் சேர்க்கப்படும்போது PVC இணைக்கப்படலாம்.

### பயன்படுத்துதல் (Using)

Pod கள் PVC களை தொகுதிகளாக பயன்படுத்துகின்றன. கொத்து PVC ஐ ஆய்வு செய்கிறது, அதற்கான இணைக்கப்பட்ட தொகுதியை கண்டுபிடித்து, அந்த தொகுதியை Pod க்கு இணைக்கிறது. பல அணுகல் முறைகளை ஆதரிக்கும் தொகுதிகளுக்கு, பயனர் தங்கள் கோரிக்கையில் Pod க்கு தொகுதியாக பயன்படுத்தும்போது விரும்பிய முறையை குறிப்பிடுகிறார்.

ஒரு பயனருக்கு கோரிக்கை இருந்து அந்த கோரிக்கை இணைக்கப்படும் வரை, இணைக்கப்பட்ட PV பயனருக்கு சொந்தமானது. `persistentVolumeClaims` சேர்க்கை (inclusion) மூலம் Pod யின் `volumes` பகுதியில் PVC இணைப்பதன் மூலம் பயனர்கள் தங்கள் Pod களுக்கு கோரிக்கையிடப்பட்ட PV ஐ அணுகலாம்.

### சேமிப்பக பொருள் பயன்பாட்டு பாதுகாப்பு (Storage Object in Use Protection)

சேமிப்பக பொருள் பயன்பாட்டு பாதுகாப்பின் நோக்கம் என்னவென்றால், ஒரு Pod ஆல் தீவிரமாக பயன்படுத்தப்படும் PVC கள் மற்றும் PVC உடன் பிணைக்கப்பட்ட PV கள் அமைப்பிலிருந்து நீக்கப்படாமல் இருப்பதை உறுதி செய்வதாகும், ஏனென்றால் இது தரவு இழப்பை ஏற்படுத்தலாம்.

ஒரு PVC ஐ ஒரு Pod தீவிரமாக பயன்படுத்துகிறது என்றால், PVC நீக்க நிலையில் (termination state) இருந்தாலும், PVC உடனடியாக நீக்கப்படாது. PVC நீக்கம் அதை தீவிரமாக பயன்படுத்தும் எந்த Pod ம் இல்லாத வரை ஒத்திவைக்கப்படுகிறது. மேலும், ஒரு PVC உடன் இணைக்கப்பட்ட PV நீக்கப்பட்டால், PV உடனடியாக நீக்கப்படாது. PV நீக்கம் PV ஐ கோரிக்கையிட்ட அனைத்து PVC களும் நீக்கப்படும் வரை ஒத்திவைக்கப்படுகிறது.

### மீட்டெடுத்தல் (Reclaiming)

ஒரு பயனர் தங்கள் தொகுதியுடன் (volume) முடித்துக்கொண்டால், API இலிருந்து PVC பொருள்களை நீக்கலாம், இது வளத்தை (resource) மீட்டெடுக்க அனுமதிக்கிறது. PersistentVolume க்கான மீட்டெடுப்பு கொள்கை (reclaim policy) கோரிக்கை வெளியிடப்பட்ட பின் தொகுதியில் என்ன நடக்கும் என்பதை கொத்திற்கு சொல்கிறது. தொகுதிகள் தக்கவைக்கப்படலாம் (Retained), நீக்கப்படலாம் (Deleted) அல்லது மறுசுழற்சி செய்யப்படலாம் (Recycled).

#### தக்கவைத்தல் (Retain)

`Retain` மீட்டெடுப்பு கொள்கை ஒரு வளத்தை கைமுறையாக மீட்டெடுக்க அனுமதிக்கிறது. PersistentVolumeClaim நீக்கப்படும்போது, PersistentVolume இன்னும் இருக்கும் மற்றும் தொகுதி "released" (வெளியிடப்பட்டது) என்று கருதப்படுகிறது. ஆனால் முந்தைய கோரிக்கையாளரின் தரவு இன்னும் தொகுதியில் இருப்பதால் வேறு கோரிக்கைக்கு இன்னும் கிடைக்காது.

ஒரு நிர்வாகி தொகுதியை பின்வரும் படிகளில் கைமுறையாக மீட்டெடுக்கலாம்:

1. PersistentVolume ஐ நீக்கவும். PV நீக்கப்பட்ட பிறகும் வெளிப்புற உள்கட்டமைப்பில் (external infrastructure, எ.கா. AWS EBS, GCE PD, Azure Disk அல்லது Cinder தொகுதி) தொடர்புடைய சேமிப்பக சொத்து (asset) இன்னும் இருக்கும்.
2. தொடர்புடைய சேமிப்பக சொத்தின் தரவை கைமுறையாக சுத்தப்படுத்தவும்.
3. தொடர்புடைய சேமிப்பக சொத்தை கைமுறையாக நீக்கவும். அதே சேமிப்பக சொத்தை மீண்டும் பயன்படுத்த விரும்பினால், அதே சேமிப்பக சொத்து வரையறையுடன் புதிய PersistentVolume ஐ உருவாக்கவும்.

#### நீக்குதல் (Delete)

`Delete` மீட்டெடுப்பு கொள்கையை ஆதரிக்கும் தொகுதி சொருகிகளுக்கு, நீக்குதல் Kubernetes இலிருந்து PersistentVolume பொருளை மட்டுமல்லாமல் AWS EBS, GCE PD, Azure Disk அல்லது Cinder தொகுதி போன்ற வெளிப்புற உள்கட்டமைப்பில் உள்ள தொடர்புடைய சேமிப்பக சொத்தையும் நீக்குகிறது. மாறும் வகையில் வழங்கப்பட்ட தொகுதிகள் StorageClass இன் மீட்டெடுப்பு கொள்கையை பெறுகின்றன, இது இயல்பாக `Delete` ஆகும்.

`Recycle` மீட்டெடுப்பு கொள்கை நிரார்த்தனப்படுத்தப்பட்டுள்ளது (deprecated). பதிலாக, மாறும் வழங்கல் (dynamic provisioning) பயன்படுத்துவது பரிந்துரைக்கப்படுகிறது.
{{< /warning >}}

தொகுதி சொருகி ஆதரித்தால், `Recycle` மீட்டெடுப்பு கொள்கை தொகுதியில் அடிப்படை சுத்தம் (`rm -rf /thevolume/*`) செய்து, புதிய கோரிக்கைக்கு மீண்டும் கிடைக்கும்படி செய்கிறது.

## PersistentVolume வகைகள் (PersistentVolume Types)

PersistentVolume வகைகள் சொருகிகளாக (plugins) செயல்படுத்தப்படுகின்றன. Kubernetes தற்போது பின்வரும் சொருகிகளை ஆதரிக்கிறது:

* `csi` - Container Storage Interface (CSI)
* `fc` - Fibre Channel (FC) சேமிப்பகம்
* `hostPath` - HostPath தொகுதி (சோதனைக்கு மட்டும்; ஒற்றை Node கொத்தில் மட்டும் வேலை செய்கிறது; உற்பத்தி கொத்துகளில் பயன்படுத்த வேண்டாம்)
* `iscsi` - iSCSI (IP மூலம் SCSI) சேமிப்பகம்
* `local` - Node களில் பொருத்தப்பட்ட (mounted) உள்ளூர் சேமிப்பக சாதனங்கள்
* `nfs` - Network File System (NFS) சேமிப்பகம்

## PersistentVolume - YAML எடுத்துக்காட்டு (PersistentVolume YAML Example)

```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv0003
spec:
  capacity:
    storage: 5Gi
  volumeMode: Filesystem
  accessModes:
    - ReadWriteOnce
  persistentVolumeReclaimPolicy: Recycle
  storageClassName: slow
  mountOptions:
    - hard
    - nfsvers=4.1
  nfs:
    path: /tmp
    server: 172.17.0.2
```

{{< note >}}
கொத்தில் பயன்படுத்த தொகுதியுடன் தொடர்புடைய உதவி திட்டங்கள் (helper programs) தேவைப்படலாம். NFS தொகுதியை பயன்படுத்தும் இந்த எடுத்துக்காட்டில், NFS ஐ பகிரவும் பொருத்தவும் `/sbin/mount.nfs` ஐ ஆதரிக்க Node களில் NFS உதவி திட்டம் நிறுவப்பட வேண்டும்.
{{< /note >}}

## PersistentVolumeClaim - YAML எடுத்துக்காட்டு (PersistentVolumeClaim YAML Example)

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: myclaim
spec:
  accessModes:
    - ReadWriteOnce
  volumeMode: Filesystem
  resources:
    requests:
      storage: 8Gi
  storageClassName: slow
  selector:
    matchLabels:
      release: "stable"
    matchExpressions:
      - {key: environment, operator: In, values: [dev]}
```

## PV இல் திறன் (Capacity)

பொதுவாக, ஒரு PV க்கு குறிப்பிட்ட சேமிப்கத் திறன் (storage capacity) இருக்கும். இது PV இன் `capacity` பண்பை (attribute) பயன்படுத்தி அமைக்கப்படுகிறது, இது Kubernetes [வள மாதிரி (resource model)](https://git.k8s.io/community/contributors/design-proposals/scheduling/resources.md) ஐ பயன்படுத்துகிறது.

தற்போது, சேமிப்கத்தின் அளவு (storage size) அமைக்கக்கூடிய அல்லது கோரக்கூடிய ஒரே வள அளவு ஆகும். எதிர்காலத்தில் `iops`, `throughput` போன்ற பண்புகளும் சேர்க்கப்படலாம்.

## தொகுதி முறை (Volume Mode)

{{< feature-state for_k8s_version="v1.18" state="stable" >}}

Kubernetes `volumeMode` புலம் இரண்டு மதிப்புகளை ஆதரிக்கிறது: `Filesystem` மற்றும் `Block`.

`volumeMode` ஒரு விருப்பமான (optional) API அளவுரு (parameter) ஆகும். `Filesystem` என்பது `volumeMode` அளவுரு தவிர்க்கப்பட்டால் பயன்படுத்தப்படும் இயல்புநிலை முறை (default mode) ஆகும்.

`volumeMode: Filesystem` ஐக் கொண்ட தொகுதி Pod களில் ஒரு கோப்பகத்தில் (directory) பொருத்தப்படுகிறது. தொகுதிக்கு காப்பிடும் சாதனம் (backing device) கட்டமைவை (block device) ஆக இருந்தால் மற்றும் அது காலியாக இருந்தால், Kubernetes முதல் முறை அதை பொருத்துவதற்கு முன் சாதனத்தில் ஒரு கோப்பு முறைமையை (filesystem) உருவாக்குகிறது.

`volumeMode: Block` ஐ அமைக்கலாம் இதனால் தொகுதி கட்டமைவு சாதனமாக (block device) பயன்படுத்தப்படும், எந்த கோப்பு முறைமையும் இல்லாமல். இது Pod க்கும் தொகுதிக்கும் இடையே மிகவும் வேகமான I/O வழிமுறையை வழங்குகிறது, Pod க்கும் சாதனத்திற்கும் இடையில் எந்த கோப்பு முறைமை அடுக்கும் (filesystem layer) இல்லாமல்.

## அணுகல் முறைகள் (Access Modes)

ஒரு PersistentVolume வளத்தை ஆதரிக்கும் எந்த வழியிலும் ஒரு ஆதார வழங்குநரால் (resource provider) ஒரு ஆதார (host) கணினியில் பொருத்தப்படலாம். கீழே காட்டப்பட்டுள்ளபடி, வழங்குநர்கள் வெவ்வேறு திறன்களைக் கொண்டிருப்பார்கள் மற்றும் ஒவ்வொரு PV இன் அணுகல் முறைகள் அந்த குறிப்பிட்ட தொகுதி ஆதரிக்கும் குறிப்பிட்ட முறைகளுக்கு அமைக்கப்படுகின்றன. எடுத்துக்காட்டாக, NFS பல வாசிப்பு/எழுத்து வாடிக்கையாளர்களை ஆதரிக்க முடியும், ஆனால் ஒரு குறிப்பிட்ட NFS PV சர்வரில் படிக்க மட்டும் (read-only) ஏற்றுமதி செய்யப்படலாம். ஒவ்வொரு PV ம் அந்த குறிப்பிட்ட PV இன் திறன்களை விவரிக்கும் தனது சொந்த அணுகல் முறைகளின் தொகுப்பை (set) பெறுகிறது.

அணுகல் முறைகள்:

* **ReadWriteOnce (RWO)** — ஒரு Node மட்டுமே தொகுதியை வாசிப்பு-எழுத்து (read-write) ஆக பொருத்தலாம். ReadWriteOnce அணுகல் முறை இன்னும் ஒரே Node இல் இயங்கும் பல Pod களுக்கு தொகுதியை அணுக அனுமதிக்கலாம்.
* **ReadOnlyMany (ROX)** — பல Node கள் தொகுதியை படிக்க மட்டும் (read-only) பொருத்தலாம்.
* **ReadWriteMany (RWX)** — பல Node கள் தொகுதியை வாசிப்பு-எழுத்து ஆக பொருத்தலாம்.
* **ReadWriteOncePod (RWOP)** — தொகுதி ஒரு Pod மட்டுமே வாசிப்பு-எழுத்து ஆக பொருத்த முடியும். முழு கொத்திலும் ஒரே ஒரு Pod மட்டும் அந்த PVC ஐ வாசிக்க அல்லது எழுத முடியும் என்பதை உறுதி செய்ய ReadWriteOncePod அணுகல் முறையை பயன்படுத்தவும். இது CSI தொகுதிகளுக்கும் Kubernetes பதிப்பு 1.22+ திற்கும் மட்டுமே ஆதரிக்கப்படுகிறது.

CLI இல் அணுகல் முறைகள் சுருக்கப்படுகின்றன:

* RWO - ReadWriteOnce
* ROX - ReadOnlyMany
* RWX - ReadWriteMany
* RWOP - ReadWriteOncePod

{{< note >}}
Kubernetes ஒரு நேரத்தில் ஒரு Node மட்டுமே PV ஐ பொருத்தலாம் என்பதை உறுதி செய்கிறது. ReadWriteOnce அணுகல் முறைடன் அமைக்கப்பட்ட PV இரண்டு வெவ்வேறு Node களில் இரண்டு Pod களால் பயன்படுத்தப்பட்டால், இது தோல்வியடையும்.
{{< /note >}}

## தேர்வாளர் (Selector)

கோரிக்கைகள் (Claims) ஒரு குறிப்பிட்ட தொகுதியை அடையாளம் காண [முத்திரை தேர்வாளர் (label selector)](/docs/concepts/overview/working-with-objects/labels/#label-selectors) ஐ குறிப்பிடலாம். தேர்வாளருடன் பொருந்தும் முத்திரைகளுடன் (labels) கூடிய தொகுதிகள் மட்டுமே கோரிக்கைக்கு பிணைக்கப்படலாம். தேர்வாளர் இரண்டு புலங்களை உள்ளடக்கலாம்:

* `matchLabels` - தொகுதிக்கு இந்த மதிப்புடன் (value) இந்த முத்திரை (label) இருக்க வேண்டும்
* `matchExpressions` - விசை (key), மதிப்புகளின் பட்டியல் (list of values) மற்றும் விசையும் மதிப்புகளும் தொடர்புடைய ஆபரேட்டர் (operator) குறிப்பிட்டு உருவாக்கப்படும் தேவைகளின் பட்டியல். `In`, `NotIn`, `Exists` மற்றும் `DoesNotExist` ஆகியவை செல்லுபடியான ஆபரேட்டர்கள்.

அனைத்து தேவைகளும், `matchLabels` மற்றும் `matchExpressions` இரண்டிலிருந்தும், ஒன்றாக AND செய்யப்படுகின்றன — பொருந்துவதற்கு அனைத்தும் திருப்திப்படுத்தப்பட வேண்டும்.

## வகுப்பு (Class)

ஒரு PV `storageClassName` பண்புடன் (attribute) [StorageClass](/docs/concepts/storage/storage-classes/) இன் பெயரை குறிப்பிட்டு ஒரு சேமிப்பக வகுப்பை (storage class) சேர்க்கலாம். ஒரு குறிப்பிட்ட வகுப்பின் PV கேவல் அந்த வகுப்பை கோரும் PVC களுடன் மட்டுமே பிணைக்கப்படலாம்.

`storageClassName` இல்லாத PV க்கு வகுப்பில்லை மற்றும் வகுப்பு இல்லாத சேமிப்பகம் கோரும் PVC களுடன் மட்டுமே பிணைக்கப்படலாம்.

## PV நிலைகள் (PV Phase)

ஒரு PV பின்வரும் நிலைகளில் (phases) ஒன்றில் இருக்கும்:

* **Available** (கிடைக்கக்கூடியது) — ஒரு கோரிக்கைக்கு இன்னும் பிணைக்கப்படாத இலவச வளம்.
* **Bound** (பிணைக்கப்பட்டது) — தொகுதி ஒரு கோரிக்கைக்கு பிணைக்கப்பட்டது.
* **Released** (வெளியிடப்பட்டது) — கோரிக்கை நீக்கப்பட்டது, ஆனால் வளம் இன்னும் கொத்தால் மீட்டெடுக்கப்படவில்லை.
* **Failed** (தோல்வியடைந்தது) — தொகுதி தன்னிலையான (automatic) மீட்டெடுப்பில் தோல்வியடைந்தது.

`kubectl describe persistentvolume <name>` கட்டளையைப் பயன்படுத்தி ஒரு PV க்கு பிணைக்கப்பட்ட கோரிக்கையின் பெயரை பார்க்கலாம்.

## தொகுதி பிணைப்பு பயன்முறை (Volume Binding Mode)

`volumeBindingMode` புலம் தொகுதி பிணைப்பு (volume binding) மற்றும் மாறும் வழங்கல் (dynamic provisioning) எப்போது நிகழ வேண்டும் என்பதை கட்டுப்படுத்துகிறது. தொகுதி பிணைப்பு முறை (volume binding mode) StorageClass பொருளில் (object) அமைக்கப்படுகிறது.

`Immediate` முறை (mode) PVC உருவாக்கிய உடனேயே தொகுதி பிணைப்பு மற்றும் மாறும் வழங்கல் நிகழும் என்பதை குறிக்கிறது. இட-வரம்புடைய (topology-constrained) சேமிப்கத்திற்கு, தொகுதி PVC இன் திட்டமிடல் தேவைகளை அறியாமல் ஒரு Node இல் பிணைக்கப்படும் அல்லது வழங்கப்படும்.

`WaitForFirstConsumer` முறை PVC பயன்படுத்தும் ஒரு Pod உருவாக்கப்படும் வரை PV ஐ பிணைப்பது மற்றும் வழங்குவதை தாமதப்படுத்துகிறது. PV கள் Pod இன் திட்டமிடல் தேவைகளால் குறிப்பிடப்படும் topology க்கு ஏற்ப தேர்ந்தெடுக்கப்படும் அல்லது வழங்கப்படும்.

## தொகுதி விரிவாக்கம் (Volume Expansion)

{{< feature-state for_k8s_version="v1.24" state="stable" >}}

PersistentVolumeClaim களை விரிவாக்குவதற்கான ஆதரவு இயல்பாக இயக்கப்படுகிறது. பின்வரும் தொகுதி வகைகளை விரிவாக்கலாம்:

* CSI
* `gcePersistentDisk`
* `awsElasticBlockStore`
* `Cinder`
* `glusterfs`
* `rbd`
* `azureFile`
* `azureDisk`
* `portworxVolume`

ஒரு PVC ஐ அதன் StorageClass க்கு `allowVolumeExpansion` புலம் true ஆக அமைக்கப்பட்டிருந்தால் மட்டுமே விரிவாக்க முடியும்.

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: example-vol-default
provisioner: vendor-name.example/magicstorage
parameters:
  resturl: "http://192.168.10.100:8080"
  restuser: ""
  secretNamespace: ""
  secretName: ""
allowVolumeExpansion: true
```

PVC க்கு அதிக சேமிப்கம் கோர, PVC பொருளை திருத்தி (edit) அதிக அளவை குறிப்பிடவும். இது PVC ஐ ஆதரிக்கும் PV இன் விரிவாக்கத்தை தூண்டுகிறது. அடிப்படை PersistentVolume ஐ விரிவாக்க புதிய PersistentVolume உருவாக்கப்படுவதில்லை. மாறாக, ஏற்கனவே உள்ள தொகுதி மறுஅளவிடப்படுகிறது (resized).

### பயன்பாட்டில் உள்ள PersistentVolumeClaim களை மறுஅளவிடுதல் (Resizing an in-use PersistentVolumeClaim)

பயன்பாட்டில் உள்ள PVC களை விரிவாக்குவது இப்போது இயல்பாக கிடைக்கிறது. PVC Pod அல்லது Deployment ஆல் பயன்படுத்தப்படும் போது, ஒரு PVC ஐ விரிவாக்க முடியும்.

புதிய தொகுதி அளவு (volume size) PVC இல் பிரதிபலிப்பதற்கு, சில நேரம் தேவைப்படலாம். தொகுதி விரிவாக்கத்தின் நிலையை `kubectl get pvc` கட்டளையை பயன்படுத்தி கண்காணிக்கலாம்.

தொகுதியை பயன்படுத்தும் Pod ஒரு கோப்பு முறைமை மறுஅளவிடுதலை (filesystem resize) கோரினால், Pod மறுதொடக்கம் செய்யப்படும் போது (restart) கோப்பு முறைமை மறுஅளவிடப்படும்.

{{< note >}}
PVC க்கான சேமிப்கம் குறைக்கப்படுவதை Kubernetes ஆதரிக்காது.
{{< /note >}}

## தொகுதிகளை Pod களில் பயன்படுத்துதல் (Using PVCs with Pods)

Pod கள் PVC களை தொகுதி குறிப்புகளாக (volume references) பயன்படுத்துகின்றன. Pod ஐ பொருத்த (mount) ஒரு குறிப்பு (reference) வழியாக:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: mypod
spec:
  containers:
    - name: myfrontend
      image: nginx
      volumeMounts:
      - mountPath: "/var/www/html"
        name: mypd
  volumes:
    - name: mypd
      persistentVolumeClaim:
        claimName: myclaim
```

## அளவிடல் வரையறைகள் (Volume Limits)

வெவ்வேறு Node களில் பல தொகுதிகளை இணைக்கும் அதிகபட்ச எண்ணிக்கை (maximum number) CSI குறிப்பில் (spec) மற்றும் Node மதிப்பீட்டாளரில் (Node evaluator) கட்டுப்படுத்தப்படுகிறது.
